# Flatter — Agent Instructions

## Project Overview
Flatter is an India-first roommate matching and shared accommodation platform for students and working professionals.

Users can discover compatible flatmates, swipe and match, chat, find vacant rooms, and form groups to rent apartments together.

**Core vision:** Find compatible people before finding a property.

## Locked Tech Stack
- **Language:** TypeScript
- **Frontend:** Next.js
- **Backend:** Express.js
- **Database:** Neon PostgreSQL
- **ORM:** Prisma
- **Authentication & User Management:** Clerk
- **Styling:** Tailwind CSS

Do not replace or introduce alternative technologies without explicit approval.

## Mandatory Agent Rules
1. **Always read and strictly follow `design.md`** before creating or modifying any UI.
2. Treat `design.md` as the single source of truth for design, layouts, typography, colours, spacing, and components.
3. Maintain consistent, responsive, production-quality UI.
4. Use TypeScript across frontend and backend.
5. Follow clean, modular, scalable architecture. Avoid unnecessary microservices.
6. Use Clerk for authentication and Neon + Prisma for application data.
7. Write reusable components, maintainable code, and secure APIs.
8. Do not add unnecessary dependencies, features, or complexity.
9. Preserve existing functionality and design consistency when making changes.
10. Build incrementally, prioritising a functional MVP.

## Product Priorities
1. User onboarding and profiles
2. Lifestyle compatibility and roommate discovery
3. Swipe, like, and mutual matching
4. Real-time messaging
5. Accommodation listings and search
6. Group formation and management
7. Safety, reporting, and moderation

**Always prioritise `design.md`, the locked tech stack, code quality, and the Flatter product vision.**
